FIR-X

Crime intelligence from FIR data, across every district

First Information Report – Intelligence Exchange · IBM Hackathon Project

FIRs sit in silos

  • Thousands of FIRs are filed by station and district, and nobody sees them together.
  • Repeat offenders who move between districts go unnoticed.
  • Crime spikes and shared methods show up only after the damage is done.
  • Analysts have no fast way to ask questions of the whole database.

One searchable system for all FIRs

AggregateCCTNS data from any district or station in a single SQLite database.
DetectRepeat offenders, inter-district criminals and crime spikes flagged automatically.
VisualiseDashboards, heatmaps and co-accused network graphs.
AskQuery the live database in plain language through the Bob LLM.

Built for police analysts, district supervisors and crime branch investigators.

Getting data in

  • CSV import maps 30+ header spellings and reads comma or tab files.
  • Dates are normalised from DD-MM-YYYY, DD/MM/YYYY, DD-Mon-YYYY and more.
  • Preview shows the mapping and warnings before anything is written.
  • Existing FIR numbers are skipped, or replaced with ?overwrite=1.
  • Every create, update and status change is written to an audit trail.

Alerts and risk scoring

Alert ruleFires when
Repeat offender3 or more FIRs
District spread3 or more districts
Method spikeSame method in 3 districts within 60 days
Crime spikeUp 40% month over month

Each accused gets a 0–100 risk score from FIR volume (30), district spread (20), crime severity (30) and prior offences (20). 70+ is Critical, 45+ High, 25+ Medium.

Run it in three commands

  • pip install flask flask-cors fpdf2 tabulate
  • python seed_data.py loads sample data, or import the 500-FIR dataset.
  • python app.py serves everything at localhost:5000.

Set BOB_API_URL, BOB_API_KEY and BOB_MODEL to turn on the AI analyst.
